2. Proposed retirement and protection of the two tools (development only — for approval; nothing done)

Part Design
Files (5; no database change) • LegacyGuard.php gets a "retired tool" refusal and a token check.
• ManualUpdateController.php: bank_recon_record_insert refuses before anything else.
• manual_update.php: that one button and its click handler are replaced by a grey "retired" note. The other Manual Update buttons are unchanged.
• BankUnrealisedValueController.php: process refuses.
• bank_unrealised_value_change.php: the Process button is replaced by the same note.
Routes and menus are not changed, so an old open page gets the refusal, not an error.
Security token Each page carries the application's security token, and both actions check it first.
• Missing or wrong token: 403 "Security token missing or expired — reload the page. Nothing was changed."
• The token check is audited separately, so forged or cross-site attempts are visible.
Second-run prevention (needed only if you later want a tool kept rather than retired) • A run-once marker in tpd_meta (legacy_run:<tool>[:<bank>]).
• A data check: the tool refuses if the entries it would write are already in the ledger. Tool A's evidence is the 21 Oct 2025 copies; Tool B's is its entry numbers.
• It also refuses for any account with a confirmed mapping, whatever the date.
Refusal messages A: "This one-off was completed on 21 October 2025 (entries 15947–16232) and has been retired. Running it again would copy the same 2024/25 entries into the ledger a second time. Nothing was changed."
B: "Bank Req Data Transfer has been retired. The 2024/25 unreconciled bank items were already carried forward on 21 October 2025, and the current ledger has no 31 March 2025 brought-forward balance to adjust. Nothing was changed."
Both are answered 409 and shown on the page.
Audit trail Every attempt writes one tpd_audit row:
• action legacy_tool_refused, with the tool, the user and their id, the time, the IP, the bank (B) and the reason (retired / token / mapped / already run);
• legacy_tool_run would record an allowed run, with the lines written.
Rollback apply.py rollback restores the 5 files from before\<time>\.
There is no schema or data change to undo. Audit rows stay, as intended.
Tests 1. Cloud copy: refusal with and without token; audit row; ledger checksum unchanged; other Manual Update buttons still work.
2. Isolated test instance, with a TEST login given the two menus there.
3. Development: data-free refusals only, ledger checksum identical.
